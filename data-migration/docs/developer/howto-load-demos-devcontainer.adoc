= How to load migrated data into the DEMOS devcontainer
:toc: left

Load the transformed `demos_app` rows into the sister `../demos` devcontainer
Postgres so DEMOS can be exercised against real migrated data. Audience: a
developer who wants to click around the app, or run a GraphQL query, against
what the migration actually produces. Success criterion: the app boots and
GraphQL returns migrated rows.

This is a *development* aid, not part of the cutover path. It ships only the
`demos_app` data onto a schema the local app created canonically via
`prisma migrate deploy`, so the scratch build's `mysql_raw` / `stg` /
`migration` schemas never reach the devcontainer.

[IMPORTANT]
====
Full parity is *not* run here. The default devcontainer scratch builds with
`SKIP_JSONSCHEMA`, so its jsonb-shape parity check is trivially green. Parity
belongs in the supabase-image environment (`make spin_up` / `make test-db-up`),
which has a real `pg_jsonschema`. See
xref:../operator/explanation-rehearsal-strategy.adoc[the rehearsal strategy].
====
