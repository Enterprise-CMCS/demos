= Explanation: the migration feasibility study and how it turned out
:toc: left

On 2026-07-09 the migration was put through a structured feasibility review -- a
"grill me" session -- to decide whether a July cutover date could be committed
to. This page preserves that review and reconciles every verdict in it against
what the repo actually shipped. Audience: anyone deciding what is in scope,
anyone re-reading the original date call, and anyone who needs to know which of
its judgements are still true. By the end you will know which PMDA entities can
migrate, which cannot, which verdicts have since been overturned, and where the
evidence for each one lives.

[IMPORTANT]
====
*Historical assessment, reconciled 2026-07-30.* Both cutover dates the study
proposed -- Fri 2026-07-17 primary and Fri 2026-07-24 fallback -- passed without
a cutover. `state/` carries no `flip`, `smoke` or `decom` gate; the newest gate
present is `parity`, marked `2026-07-28T18:25:48Z`. The only cutover date now
encoded anywhere in the pipeline is the Federal Comment past-window failsafe
constant `2026-08-20` in `sql/23_app_derived/50_application_phase.sql`.

Read <<verdicts>> before <<as-written>>. The reconciliation is current; the
preserved study text is not, and several of its verdicts are wrong today.
====

`2026-07-27T21:29:40Z`.

said, what is true today, and where to verify it.

== What the study got right, and where it drifted

Right: the mechanics. Every one of the study's GREEN mechanical verdicts is still
GREEN, and the five checks it flagged as wired-but-unproven all passed on first
validation. Right, too, about the shape of the risk -- the build crunch, not the
parity SQL, is what consumed the following three weeks.

Wrong in three directions. It treated documents as a deferred build item when the
answer turned out to be that there is nowhere in `demos_app` for the metadata to
rest, so the entity left scope entirely on 2026-07-27. It declared the sign-off
burden closed a fortnight before a new blocking question opened on a single
duplicate `medicaid_id`. And it read check 21 as safely non-gating, when the
check has since been tightened to refuse an unreviewed hold-back -- which is
exactly the class of judgement the study warned about, a mechanical rule agreeing
with the reviewer by coincidence rather than by review.

Its most durable contribution is not the date. It is the go/no-go rule, which
still names the correct gates, and the warning against conflating "we found bugs"
with "we ran a clean rehearsal."
